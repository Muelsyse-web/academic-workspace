# Local AI and Retrieval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Ask scoped questions with verifiable sources, configurable local models, optional embeddings and persistent conversations.
**Architecture:** Provider transport has no DB/file access and rejects non-loopback endpoints. AI service retrieves source chunks, builds bounded evidence, validates model citations, then persists history. Embeddings retain provider/model/dimension/version metadata.
**Tech Stack:** httpx, FastAPI, SQLite, React Markdown/KaTeX and deterministic test providers.

### Task 1: Provider transport
Files: `backend/workspace/providers.py`, `backend/tests/test_providers.py`.
- [ ] Test `LocalProvider(base_url,model,embedding_model,timeout,api_key)` rejects remote addresses, embedded credentials and redirects; MockTransport asserts chat and embedding wire payloads without network.
- [ ] Implement `.models()`, `.chat(messages)`, `.embed(texts)` using trust_env=False and bounded timeout, converting connection/schema errors into safe ProviderError. Check embedding count, finite numbers and common dimension.
- [ ] Run provider tests and review local-only boundary.

### Task 2: Evidence and conversations
Files: `backend/workspace/ai.py`, `backend/workspace/migrations/003_ai.sql`, `backend/tests/test_ai.py`.
- [ ] Settings GET/PUT `/settings/provider` stores public configuration; API key stored only in separate project-local 0600 secret file, never returned or included in backup. `/settings/provider/test` reports models and failure. Defaults LM Studio 127.0.0.1:1234/v1, no model selected.
- [ ] Conversation GET/POST/list/delete routes, POST `/conversations/{id}/messages` with content. Course/document scope persisted on conversation, verified on creation, applied to every retrieval.
- [ ] Retrieve up to 6 chunks and max 12000 characters, send system prompt marking source text untrusted; ask for JSON {answer,citations:[{id,quote}],insufficient_evidence}. Validate IDs against exact current evidence; quote is nonempty substring. Citation metadata comes from DB. Invalid or missing refs produce unverified status and visible warning; no sources produces evidence_insufficient without model call.
- [ ] Persist user and assistant content, status, immutable source snapshot and provider errors. Deletion removes conversation messages only. Model unavailable returns actionable failure while keeping user message.
- [ ] MockProvider injected only via app.state in tests, never exposed as fake real provider. Tests cover real source lookup, fabricated citations, misleading quote, unavailable provider and scope isolation.

### Task 3: Optional semantic retrieval
Files: `backend/workspace/embeddings.py`, tests.
- [ ] Embedding settings separate from chat model. POST `/embeddings/reindex` records batched local vectors for active chunks; progress and failure visible. Scope/filter before cosine scoring, fuse keyword+semantic results for hybrid mode.
- [ ] Track model, endpoint, dimension and active version. Mismatched configuration never mixes vectors; fall back explicitly to keyword when service/index unavailable.
- [ ] Tests use deterministic vectors to prove semantic retrieval of nonliteral synonyms, correct filters, count/dimension checks and model switching.

### Task 4: UI and evidence
Files: `frontend/src/pages/Chat.tsx`, `Settings.tsx`, Search enhancement and tests.
- [ ] Implement model config, connection test, conversation list/scope selection, messages, copyable Markdown, visible citation cards and source links. Show generating/error/insufficient/unverified status.
- [ ] Connect real local LM Studio when available; record current default endpoint refused connection, do not label Mock tests as real inference.
